# 设计文档:评审前的「提问闸门」

日期:2026-05-29
关联 skill:`product-restraint`(产品克制)

## 背景与动机

现有 skill 是**一次性评审**:用户抛出想法,skill 直接按六维评分卡评判,用户没讲清的地方按「缺失即风险」判红。

问题:很多想法在用户脑子里其实有答案,只是初次描述没说全;直接判红虽然安全,但评审的**准确性**会打折——把"没说"误当"没想清"。本次改动在评审前插入一个**提问闸门**,先把评审最依赖、最常说不清的关键事实当面问清,再评审,从而提升评审准确性。

关键前提:提问**不能**把 skill 从"怀疑的顾问"软化成"捧场的澄清助手"。因此提问被定义为**逼问式举证**,而非温柔澄清。

## 核心决策(已与用户对齐)

| 维度 | 决策 |
|---|---|
| 性格调和 | **升级「缺失即风险」为「先逼问,答不上判更红」**。提问是把六维关键空白当面摊给用户;能答→答案变评分证据,答不上来→该维判更红,且比被动判红更有杀伤力。默认怀疑、举证责任在用户**不变**。 |
| 拷问形式 | 后三个「灵魂拷问」**也走 `AskUserQuestion` 选择题**,但选项**故意扎心**——把"假需求的典型表现"做成选项,逼用户对号入座。 |
| 非交互回退 | 检测到 `AskUserQuestion` 不可用(如 `test.sh` 的 `claude -p`)→ **跳过提问,回退一次性评审**,未答维度按「缺失即风险」判红。evals 照常能跑。 |
| 已答是否再问 | **自适应**:用户初始描述里已讲清的维度跳过,把名额留给真空白和最尖锐拷问,避免问废话。实际可能少于 6 问。 |

## 提问闸门设计

### 流程位置

插入为评审流程**第 0 步**,在「先复述」之前:

```
第 0 步 提问闸门(本次新增)
   ↓
第 1 步 先复述理解到的想法(纳入用户回答)
   ↓
第 2 步 逐维度评分卡
   ↓
第 3 步 Premortem
   ↓
第 4 步 三部分输出
```

### 提问规则

- 最多 **6 问**,分两批,每批 ≤4 问 → 每批一次 `AskUserQuestion` 调用(工具单次上限 4 问)。
- **自适应**:初始描述已讲清的维度跳过对应问题;若自适应后总数 ≤4,可合并为一次调用。
- 都是**选择题**(`AskUserQuestion` 会自动附带 "Other" 供自由作答)。
- **非交互回退**:工具不可用 → 跳过整个闸门,直接进第 1 步,走一次性评审。

### 第一批 · 需求收集/确认(映射前几维)

选项设计区分"有证据 vs 脑补":

| # | 问什么 | 映射维度 | 扎心选项示例 |
|---|---|---|---|
| 1 | 核心用户是谁、现在怎么解决的 | 真需求度 | 已在用某种笨办法/付费工具 · 我自己脑补的 · 还没去观察过 |
| 2 | 凭什么不被现有方案 or 大厂替代 | 价值与差异 | 有独有数据/深度工作流 · 体验更好 · 说不出具体差异 |
| 3 | 用户为此付费/高频使用的意愿 | 商业账 | 有人已为类似东西付过钱 · 应该会愿意吧 · 免费才会用 |

### 第二批 · 灵魂拷问(故意扎心,映射克制度/真需求度)

| # | 问什么 | 映射维度 | 扎心选项示例 |
|---|---|---|---|
| 4 | 这需求的真实来源 | 克制度 | 见过≥5个真实用户主动抱怨 · 我自己就想要(n=1) · 因为 AI 让它能做了 |
| 5 | 不做会怎样 | 真需求度 | 有人会主动来催我做 · 用户继续用老办法,没人找我 |
| 6 | 验证到什么程度了 | 真需求度 | 有人已付费/已用笨办法解决 · 问过但都说"听起来不错"(恭维) · 还没问过任何真实用户 |

### 答案如何进评分卡(守住命门)

- 选了**有证据**的选项(已付费、已用笨办法、有独有数据)→ 对应维度可往黄/绿调。
- 选了**暴露空白**的选项(自己想要、还没问过、说不出差异),或用 Other 写含糊内容,或避而不答 → 该维**直接更红**,并在详细说明里点明"当面被问到都答不上,比没问更说明问题"。
- 默认怀疑不变:**举证责任仍在用户,提问只是给一次举证机会。**
- 第 1 步复述纳入回答:"基于你确认的事实,我这样评……",体现评审建立在用户亲口确认之上。

## 不变量复核(改完不能破坏)

1. 默认怀疑,举证责任在用户 —— **保留**(提问只是给举证机会)。
2. 缺失即风险 —— **升级**为"先逼问,答不上更红"(本次唯一被改写的不变量)。
3. 拒绝套话否定 —— **保留并强化**(红灯理由要引用用户的具体选择)。
4. 三部分输出模板,顺序固定 —— **保留**(提问闸门在三部分之前,不改三部分本身)。
5. 给放行路径但门槛高 —— **保留**。

## 非目标(YAGNI)

- 不做多轮反复追问(闸门只问一轮,≤6 问,问完即评)。
- 不新增带模拟回答的 eval 用例(本期只保证回退路径下老用例可跑)。
- 不改 frontmatter description / 不动触发逻辑。
- 不做 Web 自动市场调研。
