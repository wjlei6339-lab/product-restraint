# 专业 HTML 报告渲染 — 设计文档

- 日期:2026-05-29
- 状态:已与用户对齐,待 review
- 关联需求:`feat:将本项目最后生成的报告以专业的 HTML 呈现,从可读性、专业性角度增加功能`

## 1. 背景与目标

本项目是一个 Claude Code skill(`product-restraint`),评审产品想法后产出**三部分 Markdown 报告**:

1. 一、可行性评价(总体倾向「别做/再想想/可以试」+ 六维评分卡,灯色 🔴🟡🟢)
2. 二、简要概述(3–5 句,点出最致命 1–2 点)
3. 三、详细说明(逐维度展开 + Premortem + 最小验证动作 + 可选重启条件)

报告目前只有终端 Markdown 形态,存在 `workspace/iteration-*/eval-*/output.md`。

**目标**:在不改变评审 prose 行为的前提下,增加一个**渲染层**,把报告转成**专业、可读、可分享、可打印**的 HTML。两种入口:① skill 评审末尾即时产出;② 批量渲染 workspace 最新一批 + 汇总索引。

## 2. 非目标

- 不改变评审逻辑、评分维度、输出模板措辞——HTML 只是同一份报告的另一种呈现。
- 不引入第三方依赖(不装 markdown 库 / pandoc / 模板引擎)。
- 不做通用 Markdown→HTML 引擎;只针对本项目报告的固定结构做语义化解析。
- 不做服务端 / 在线托管;产物是可离线打开的本地单文件。

## 3. 用户已确认的决策

| 维度 | 决策 |
|---|---|
| 用途/受众 | 既发给别人看也自己归档 → 需自包含单文件 + 封面 + 历史索引 |
| 形态/触发 | skill 评审时直接输出 HTML(经由确定性脚本,非 LLM 手搓) |
| 输入范围 | 最新一批 iteration + 汇总索引 |
| 视觉风格 | 简洁商务白底(细线表格、克制配色、印刷友好) |
| 即时模式落点 | 当前工作目录,文件名 `产品克制-评审-<想法标题>-<日期>.html` |
| 是否每次自动生成 | 自动生成(容错跳过),不额外询问 |
| 生成物是否入 git | gitignore(属产物) |

## 4. 架构(方案 A)

确定性渲染脚本 `render.py` 承载全部渲染逻辑与样式(唯一真源),skill 与 test.sh 都**调用**它,不各自实现 HTML。

```
                ┌──────────────┐
  skill 评审末尾 ─▶│              │─▶ ./产品克制-评审-<标题>-<日期>.html
                │  render.py   │
  test.sh 收尾 ──▶│ (解析+模板)  │─▶ workspace/iteration-*/eval-*/report.html
  手动命令行 ────▶│              │   + workspace/iteration-*/index.html
                └──────────────┘
```

理由:HTML 样式集中、稳定、一致;SKILL.md 不被长模板撑臃肿;即时产出与批量渲染共用一个引擎。

## 6. `render.py` 详细设计

### 6.1 CLI

- `python3 render.py --latest`
  扫描 `workspace/` 下时间戳最大的 `iteration-*` 目录,渲染其中每个 `eval-*/output.md` 为同级 `report.html`,并在该 iteration 根生成 `index.html` 汇总索引。test.sh 走这条。
- `python3 render.py <file.md> [-o <out.html>] [--title "想法一句话"]`
  渲染单个报告。`-o` 缺省时输出到输入同目录同名 `.html`。skill 即时产出走这条(skill 传 `--title` 与 `-o`)。
- `python3 render.py --all`
  遍历所有 `iteration-*`,各自渲染 + 索引。
- 无法解析为合法报告时:打印告警到 stderr,退出码非 0,但不抛栈;批量模式下跳过坏文件、继续其余。

### 6.2 语义化解析(针对固定结构,非通用 md)

报告结构稳定,解析锚点:

- **序言段**:`## 一、可行性评价` 之前的文本(复述/非交互说明),作为可选副标题来源与"评审引言"。
- **总体倾向**:正则 `总体倾向[::]\s*\**\s*(别做|再想想|可以试)`。
- **评分卡**:定位 `## 一、可行性评价` 后的 Markdown 表格,逐数据行解析三列「维度 / 灯 / 理由」;灯列含 `🔴|🟡|🟢` 之一。
- **简要概述**:`## 二、简要概述` 到 `## 三、详细说明` 之间正文。
- **详细说明**:`## 三、详细说明` 之后正文,内部进一步识别三个固定块:
  - `**Premortem …**` 起的块 → 警示框
  - `**…先花最小成本验证…**` 起的块 → 行动框
  - `**重启条件…**` 起的块 → 信息框
  - 其余维度展开段落正常渲染。
- 解析按"尽力而为":缺某块就略过对应区域,不报错(报告偶尔会省略重启条件)。

### 6.3 行内 Markdown 转换(轻量)

只支持报告里实际用到的:`**粗体**`、`` `code` ``、`---` 分隔线、`- ` 无序列表、`1. ` 有序列表、空行分段。统一做 HTML 转义,防止报告正文里的 `<` `>` `&` 破坏页面。

### 6.4 灯色映射

| emoji | 语义 | 颜色 | 渲染 |
|---|---|---|---|
| 🔴 | 红 | 危险红 | 实心红圆点 + 文字「红」 |
| 🟡 | 黄 | 警示黄 | 实心黄圆点 + 文字「黄」 |
| 🟢 | 绿 | 通过绿 | 实心绿圆点 + 文字「绿」 |

不靠裸 emoji 上色(打印不显色);用 CSS 圆点 + 文字标签。

### 6.5 标题来源

优先级:`--title` 参数 > eval 目录名(去 `eval-N-` 前缀、连字符转空格)> 文件名。副标题尝试取序言里复述首句的精炼。

## 7. HTML 视觉结构(简洁商务)

- **字体**:中文友好系统栈 `-apple-system, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif`。
- **封面区**:报告名「产品克制 · 可行性评审报告」+ 想法标题 + 评审日期 + 总体倾向**大徽章**(别做=红 / 再想想=黄 / 可以试=绿)。
- **锚点目录**:一/二/三 + Premortem + 最小验证动作,点击跳转。
- **评分卡**:细线表格,每行 = 维度 + 灯色圆点徽章 + 理由,行左侧按灯色加细色条。
- **简要概述**:醒目引用块(用户最常只读这段)。
- **详细说明**:逐维度段落;Premortem → 红边浅红底警示框;最小验证动作 → 绿/蓝边行动框;重启条件 → 中性信息框。
- **印刷友好**:`@media print` 控分页 + `print-color-adjust: exact` 保色;隐藏目录交互态。
- **响应式**:`max-width` 容器居中,窄屏自适应。
- **index.html**:逐条列出本批报告 = 想法标题 + 结论徽章 + 六维迷你灯条 + 指向 `report.html` 的链接。

## 8. 两条产出路径分工(避免互相干扰)

- **即时(skill 内)**:评审仍在终端正常输出三部分 Markdown(不变);紧接着调 `render.py <报告md> -o <当前目录/产品克制-评审-标题-日期.html> --title "…"`,落地后用一句话告知路径。
  **复用 skill 既有交互判断**:能与真人来回的交互会话才生成;`claude -p` 批处理 / 无法发问的环境**静默跳过**(与「提问闸门非交互回退」同一套逻辑)。
- **批量(test.sh)**:所有 eval 跑完后由 test.sh 统一 `python3 render.py --latest`。
  因此 `claude -p` 评测时 skill 内那步会跳过,渲染统一由 test.sh 收尾——**两条路不会在 eval 目录里乱写文件**。

## 9. SKILL.md 接入(措辞要点)

在「评审流程」第 4 步「按三部分输出」之后,新增一步,核心语义:

> 评审输出后,若当前是可与用户交互的真实会话,调用 skill 目录下的 `render.py` 把本次报告渲染成专业 HTML 落到当前工作目录,并用一句话告知文件路径(便于转发/归档)。若处于非交互批处理(如 `claude -p`)或无法写文件,静默跳过此步,不影响评审本身。

约束:措辞简短,不破坏既有五原则与模板;明确这一步是"附加交付",失败不影响评审。

## 10. test.sh 接入

在脚本结尾「全部完成」之前/之后,增加:

```bash
# 把本批报告渲染成专业 HTML + 汇总索引(渲染失败不阻断测试)
python3 render.py --latest || echo "  ⚠ HTML 渲染跳过(见上)"
```

确保渲染失败不影响 `set -e` 下的测试结论(用 `|| true` 式兜底)。

## 12. 必须守住的不变量

- HTML 是**渲染层**,不得改变评审 prose 行为、维度、模板(CLAUDE.md 既有不变量不被稀释)。
- 零第三方依赖。
- skill 内生成步骤**失败/非交互必须静默跳过**,绝不影响评审输出本身,也不污染 evals 输出。
- `render.py` 是 HTML 样式的唯一真源,skill 与 test.sh 只调用、不复制样式。
